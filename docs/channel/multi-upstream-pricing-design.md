# 多上游渠道报价导入与分组上架方案

第一版接入 Kedaya 和 String AI。管理员在「上游渠道」导入报价，为来源的每个分组分别配置上游 API Key 和本站售价倍率，预览组内模型售价后整组上架。首次导入时，系统分配渠道 ID。渠道名默认使用来源名称，渠道分组名默认使用上游原分组名，本站销售分组名默认使用「渠道ID_原分组名」。这三个名称均可单独编辑。后续导入同一个渠道时复用渠道 ID 和已有分组。

[后台交互草图](./channel-quotes-prototype.html) · [后台界面预览](./channel-quotes-prototype.png)

## 后台操作入口

在默认主题的「渠道 → 上游渠道报价」中选择 Kedaya 或 String，点击「获取最新报价」，也可以上传来源的 JSON 快照或统一 JSON。预览导入差异后确认保存。公开目录价格在核对之前显示为估算。选中分组后可分别修改渠道名、渠道分组名和本站销售分组名，配置该组实际使用的 API 地址、协议、Key 和售价倍率。导入的模型可在「编辑报价」中核对计费档位、映射和端点，确认成本与 API 用量后再整组上架。图片规格与视频用量可用于比价。

## 1. 渠道、分组与报价

| 对象 | 记录粒度 | 保存内容 |
| --- | --- | --- |
| 导入渠道 | 每个独立导入的上游渠道 | 系统生成的渠道 ID、可编辑的渠道名、来源、来源地址、导入批次 |
| 渠道分组 | 导入渠道 × 上游分组 | 上游分组标识和原名、可编辑的渠道分组名和本站销售分组名、分组专用的上游 Key、本站售价倍率、当前上架版本 |
| 上游报价 | 渠道分组 × 上游模型 ID | 原始单位和单价、官方参考价、档位和条件、核验状态、采集时间和报价版本 |
| 分组上架版本 | 每次整组上架或更新上架 | 已确认的模型范围、每个模型的报价版本和最终售价、组内执行渠道和生效状态 |

### 渠道 ID 与分组命名

- **首次导入**时，保存该上游渠道并分配一个渠道 ID，渠道名默认填入来源名称，例如 Kedaya。渠道分组名默认填入上游原分组名，例如「DeepSeek 特殊渠道」。同一渠道下各分组共用该渠道 ID，本站销售分组默认命名为「渠道ID_原分组名」，例如 `1001_DeepSeek 特殊渠道`。
- **修改名称**时，管理员可在分组详情中分别编辑渠道分组名和本站销售分组名。比如，可以把后台的渠道分组名改为「DeepSeek 主线」，并单独设置用户看到的销售分组名。渠道和分组按各自的标识关联，已有授权、已发放的本站 API Key 和上架记录继续关联原分组。
- **重复导入**时，管理员从已有渠道发起更新，系统复用渠道 ID，并保留自定义的渠道名、渠道分组名、本站销售分组名、Key 和售价倍率。新出现的分组按首次导入规则填写默认名称。模型报价按渠道分组和上游模型 ID 更新，相同内容复用原报价版本。
- 匹配上游分组时优先使用来源内的稳定 ID。只有分组名时，用平台和规范化后的上游原分组名匹配。来源改名且无法自动匹配时，管理员可将其关联回已有分组。

下面的 ID 由系统分配，表中数值用于说明命名方式。

| 导入渠道 | 上游原分组名 | 默认本站销售分组名 | 组内模型示例 |
| --- | --- | --- | --- |
| Kedaya · `1001` | DeepSeek 特殊渠道 | `1001_DeepSeek 特殊渠道` | `deepseek-v4.1-flash`、`deepseek-flash` |
| Kedaya · `1001` | GPT 0.05 不降智 | `1001_GPT 0.05 不降智` | `gpt-6.2-sol`、`gpt-6.2-astra` |
| String AI · `1002` | OpenAI | `1002_OpenAI` | `gpt-6.2-sol` |
| String AI · `1002` | OpenAI【UltraFast 8倍速】 | `1002_OpenAI【UltraFast 8倍速】` | `gpt-6.2-sol` |

同一个本地模型可以在多个本站销售分组上架。用户通过现有分组授权选择本站 API Key 的销售分组，按该分组的售价和路由调用。导入渠道 ID 用于分组命名。后台复用现有渠道实体执行 API 请求，执行渠道记录自己的 ID、模型映射和可用能力。 [渠道实体](../../model/channel.go#L22) · [渠道能力](../../model/ability.go#L16) · [用户分组](../../service/group.go#L10)

## 2. 导入与分组配置

1. 管理员选择 Kedaya 或 String，上传报价快照并预览上游分组、模型和分项单价。第一版支持使用已登录浏览器采集的快照，也支持填表导入统一 JSON。
2. 确认保存后，左侧列表按「渠道名 → 渠道分组名」展示导入结果，分组详情展示上游原分组名与本站销售分组名。重新导入时，预览新增、涨跌、缺价和本次未见条目，并列出上下文门槛、缓存费率和峰谷时段的变化。部分采集失败时，只更新成功读取的报价。已上架版本继续使用发布时引用的报价。
3. 打开一个分组，填写该分组实际使用的上游 API Key。报价快照保存来源和价格，凭证通过分组设置单独录入。每个分组单独保存和轮换 Key，界面只显示掩码和末尾字符。用户发起请求时使用本站 API Key，后台按其销售分组选取上游凭证。
4. 设置该分组的本站售价倍率。页面即时展示组内各模型的上游实付价、本站售价和预估毛利率。已有同名本地模型可复用映射，后台在上架前校验该分组的实际 API 渠道、模型映射及端点用量。
5. 点击「上架该分组」。后台根据该组的 Key 和已确认的模型映射准备执行渠道，把预览中的模型、售价和路由作为一个分组版本发布。管理员在上游分组页面完成操作。

### 两家导入适配器

| 来源 | 应读取的内容 | 需要人工核验的情况 |
| --- | --- | --- |
| Kedaya | 分组、模型 ID、实付价、页面官方参考价、倍率、上下文或时段档位、缓存读写、图片规格 | 分组总倍率与模型行不同、字段为 `-`、特殊缓存时长、页面未显示完整计费条件 |
| String | 平台与子渠道、模型 ID、默认积分价及 USD 展示价、详情中的缓存价格、长上下文和峰谷规则、图片规格与视频秒价 | 积分购入成本、页面舍入精度、账号可用子渠道、仅展示起价的媒体模型 |

Kedaya 优先读取模型行的实付价，分组倍率随原始报价留档。String 同一条报价保存原始积分和 USD 展示值，页面倍率只作来源说明。账号成本优先取管理员设定的协议价或每积分实际购入成本。只有页面价时可参与估算并标记口径。导入用分档记录保存阈值及比较符号、峰谷的时区和周期、缓存读写及 TTL、图片规格与视频分辨率和计费用途。明确的零价和未提供价格分别保存。String 页面调用的报价接口在无授权头时返回 401，第一版以页面快照作为可用入口。 [Kedaya 模型广场](https://kedaya.ai/model-plaza?embedded=1) · [String 定价页](https://www.string.ink/dashboard/pricing)

### 本站售价倍率

**本站最终单价 = 已确认的上游实付单价 × 本站售价倍率。** 上游折扣用于说明来源价格。比如 Kedaya 的 `0.05×` 已计入页面显示的实付价，计算本站售价时直接用实付价乘本站倍率。String 的积分报价先按确认的积分购入成本换算，有协议价时可按已确认的协议价作为该组成本。以展示价估算的结果在预览中标明口径。

以 `1001_DeepSeek 特殊渠道` 中的 `deepseek-v4.1-flash` 为例，管理员设置 **1.30×**，售价和成本均以 USD／百万 token 展示。

| 计费项 | 上游实付 | 本站售价 |
| --- | ---: | ---: |
| 普通输入 | $0.05 | $0.065 |
| 输出 | $0.20 | $0.26 |
| 缓存读取 | $0.001 | $0.0013 |

按上游成本估算，该倍率对应的毛利率为 **23.08%**，计算式为 `（售价 − 上游成本）÷ 售价`。分组上架时保存使用的倍率和派生出的最终单价，线上展示与结算直接使用最终单价。

### 保持来源计费规则

| 来源规则 | 售价生成方式 |
| --- | --- |
| 基础 token 价、显式缓存读写价或固定次价 | 分别对各项已确认成本应用本站售价倍率，保留原计费单位 |
| 长上下文阶梯 | 保留 `≤`、`>` 等边界，用完整输入长度 `len` 选档，再对各档单价应用倍率 |
| 峰谷统一倍数 | 按来源时区和窗口保留时段倍数，本站售价倍率应用于分项基准价 |
| 峰谷分项费率或长上下文与峰谷组合 | 按各条件分支单独换算单价，用 `tiered_expr` 保留档位与时间规则 |
| 缺价、边界或用量语义待核验 | 保留原始内容，在预览标出待核验项。端点可能用到的计费项需确认后才能上架 |

现有表达式编辑器用于复核派生出的表达式。表达式系数采用最终 USD／百万 token 单价，缓存变量仍按实际用量语义分别计价。 [本站定价编辑器](../../web/default/src/features/system-settings/models/model-pricing-sheet.tsx#L432) · [计费表达式](../../pkg/billingexpr/expr.md)

## 3. 按实际用量对比成本

后台选择同一个本地模型和一份用量场景，逐条展示普通输入、缓存读取、缓存写入、输出、命中档位、总成本和按分组售价倍率或统一试算售价计算的毛利。用完整输入长度选择阶梯，计费时按互斥的 token 类别相加。时间、时区及阈值边界按每个上游报价的规则计算。媒体用量输入张数、分辨率和质量，或生成与参考视频秒数。价格缺失且场景用到了该计费项时，标为「成本待确认」。编辑页默认用最新报价试算，已上架的分组版本保留当时引用的报价版本，管理员可切换查看两版差异。

例如 `gpt-6.2-sol` 的基础档，用量为 **10 万普通输入 + 1 万输出**，统一对比用的试算售价为输入 $0.24、输出 $1.20 / 百万 token。所有金额为美元，成本按报价页的展示精度试算。

| 渠道 | 输入 / 百万 | 输出 / 百万 | 预估成本 | 同售价预估毛利 |
| --- | ---: | ---: | ---: | ---: |
| String · OpenAI | $0.06 | $0.30 | $0.009 | $0.027 |
| Kedaya · GPT 0.05 | $0.10 | $0.50 | $0.015 | $0.021 |
| String · UltraFast | $0.18 | $0.90 | $0.027 | $0.009 |

若改用 **2 万普通输入 + 8 万缓存读取 + 1 万输出**，按页面所示的缓存读取价，String 普通 OpenAI 约 $0.00444，Kedaya GPT 0.05 约 $0.00740。String 页面上的缓存命中率、首字耗时和可用率可供选渠参考，价格计算使用分项单价。DeepSeek Flash 应同时试算空闲和高峰，String 两档分别为 $0.03 / $0.12 与 $0.06 / $0.24，Kedaya 特殊渠道展示的是 $0.05 / $0.20。 [String 定价页](https://www.string.ink/dashboard/pricing) · [Kedaya 模型广场](https://kedaya.ai/model-plaza?embedded=1)

## 4. 整组上架、更新与下架

后台「上游渠道」左侧显示渠道名和渠道分组名。右侧分组详情可编辑渠道分组名和本站销售分组名，并配置上游 Key、本站售价倍率和预览组内模型价格。分组状态显示「待配置」「待上架」或「已上架」。保存配置后，可以直接从这里上架该组。未配置 Key 的分组可以预览售价，配置有效 Key 后即可提交上架。

「上架该分组」以一次后端提交激活整个分组版本。预览列出本次可上架的全部模型，以及按[第一版发布范围](#第一版发布范围)仅保存报价的条目。后台校验组内模型、售价规则及执行渠道。预览中列为可上架的模型如有一项校验失败，整次提交保持原生效状态，后台显示失败模型及原因。发布时一并写入分组模型清单、最终单价和执行渠道，模型列表、价格展示和 API 路由读取同一个生效版本。

已上架分组再次导入报价或预览新的倍率时，当前线上版本继续生效。点击「更新已上架分组」后，新的报价和派生售价一同生效。并发提交按草稿基准版本检查。历史版本可复制后重新上架，并重新校验当前渠道。下架整个分组后，新请求和价格列表同步应用下架状态，进行中的请求仍按锁定版本结算。

## 5. 路由与扣费接入

- **首次选渠。** 分发中间件确定请求实际销售分组后，读取该分组的生效版本。请求模型需在版本清单中，执行渠道需已启用、具备该分组的模型能力，并使用该分组的 Key。亲和、指定渠道及现有备选渠道均在该分组的有效候选内应用。 [首次分发](../../middleware/distributor.go#L30) · [渠道选择](../../service/channel_select.go#L83)
- **预扣和结算。** 预扣前锁定销售分组、上架版本、模型的最终单价或表达式、成本报价版本及请求开始时刻。峰谷条件始终使用请求开始时刻，长上下文结算使用实际完整 `len`。显式发布价的有效结算倍率为 `1`，分组售价倍率已包含在最终单价中。用户组专属优惠继续作用于原有定价路径。 [预扣与重试](../../controller/relay.go#L153) · [表达式结算](../../pkg/billingexpr/settle.go#L19)
- **重试与日志。** `auto` 可以在首次选渠时确定销售分组。进入预扣后，重试保留同一销售分组和上架版本。候选耗尽时走现有失败和退款流程。后台日志记录销售分组、实际执行渠道 ID、上架版本、成本报价版本和用量。上游凭证只用于转发，用户可见页面和接口展示本站销售分组名、模型和最终售价。 [重试选渠](../../controller/relay.go#L292) · [文本结算](../../service/text_quota.go#L361)
- **兼容已有定价。** 沿用旧配置的原有模型和分组继续使用现有模型全局定价。导入分组的模型以生效版本为准，只有已上架的模型会进入价格列表并接收新请求。 [现有价格接口](../../controller/pricing.go#L36)

## 6. 第一版交付与验收

### 第一版发布范围

| 计费方式 | 第一版处理 |
| --- | --- |
| 文本按 token 计价 | 组内符合端点用量的模型可上架，包含基础输入、输出与端点能提供的缓存读写用量 |
| 文本动态 token 计价 | 可上架，复用 `tiered_expr` 支持长上下文与峰谷组合 |
| 固定按次计价 | 已支持固定次价且已接入分组售价快照的端点可上架 |
| 按图片规格或视频时长计价 | 可导入、保存和比价，待端点接入实际计费用量和售价快照后开放上架 |
| 计费规则缺失或用量待核验 | 保留原始报价和待核验状态，预览展示原因 |

### 验收场景

1. 首次导入 Kedaya，系统生成一个渠道 ID，渠道名默认填入 Kedaya，各渠道分组名默认填入上游原分组名。DeepSeek 和 GPT 的本站销售分组名使用同一个 ID 前缀。首次导入 String 时生成另一个渠道 ID。
2. 分别修改 Kedaya 的渠道名、一个渠道分组名和该组的本站销售分组名，验证后台与用户侧显示各自的名称，已有授权和本站 API Key 仍指向原分组。再次导入，确认复用原渠道 ID，保留三个自定义名称、上游 Key 和售价倍率。相同内容复用报价版本，变价产生新版本。
3. 为同一渠道下两个分组分别设置不同的 Key 和售价倍率。验证后台显示掩码，轮换其中一组的 Key 后，实际请求仍各自使用所属组的 Key。缺少 Key 的分组无法上架。
4. 以 DeepSeek 分组的 `1.30×` 为例，核对组内模型售价预览、价格页和 API 实际扣费。上架时整组的模型和售价一起生效。任一预览为可上架的模型校验失败时，线上版本保持原状态。
5. 将同一个 `gpt-6.2-sol` 上架到 Kedaya 和 String 的销售分组。验证两个组各用自己的 Key、报价和售价。验证长上下文边界和峰谷窗口，跨窗口请求按开始时间确定峰谷，按实际输入长度确定上下文档。
6. 对已上架分组重新导入涨价报价或调整倍率，确认新售价只在「更新已上架分组」后生效。跨版本请求沿用锁定版本。整组下架后，价格和路由同时应用下架状态。
